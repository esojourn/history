# 内容撰写与查证规范

这份规范管两件事：**文字怎么写**，**事实怎么查**。人写、AI 写都按它来。数据格式的总体设计见 [plan.md](plan.md) 第 4 节，这里只写录入时要照做的部分。

## 0. 底线

1. **来源必须如实标明。**（2026-11-21 项目方确定）内容可以先由 AI 凭训练记忆写，以后再慢慢查证补充；但每一条都要让读者看得出它的来源是哪一种：
   - 实际查阅过的可信出处 → 写进 `sources`，带网址；
   - 凭记忆标注、没有核对过的书目 → 写进 `recalled`；
   - 两样都没有 → 网站自动注明"由 AI 模型 Claude Fable 5.2 凭训练记忆写成"。
   **绝不能把没查过的东西写进 `sources` 冒充查过。**
2. **不编造**：凭记忆写，指的是写确实知道的史实；不编对话，不编数字，不编细节，不补"合理的想象"。拿不准的不写。
3. **有争议就写明有争议**，不替史料选边；传说、后世演义要标明"相传""据《某书》"。
4. **不确定宁可不写。** 一条只有两段、句句有据的介绍，好过一条四段、掺了猜测的介绍。

## 1. 每个人物、事件有两个文件

| 文件 | 内容 | 语言 |
|---|---|---|
| `data/person/<id>.yaml`、`data/event/<id>.yaml` | 年份、地点、参与者等结构数据 | 与语言无关 |
| `locales/zh-CN/person/<id>.yaml`、`locales/zh-CN/event/<id>.yaml` | 名称、简介、正文、出处 | 中文 |

`id` 一旦确定不再改。

## 2. 文字文件

```yaml
name: 韩信
aliases: [淮阴侯]            # 别名、封号、本名；没有就写 []
role: 大将军                 # 人物才有；一个短语
summary: 汉初名将，助刘邦击败项羽，后被吕后处死。
body: |-
  第一段……

  第二段……
sources:
  - 《史记·淮阴侯列传》 https://ctext.org/shiji/huai-yin-hou-lie-zhuan/zhs
recalled:                    # 凭记忆标注、还没核对的；没有就不写这一项
  - 《汉书·韩彭英卢吴传》
```

- `summary`：一句话，40 字以内，说清"他是谁 / 这是什么事"。
- `body`：**所有人物、事件都要写**。
  - 重要度 3 及以上：3-5 段左右，450–750 字。
  - 重要度 1–2：至少 2-3 段，220–450 字。史料确实很少的（如只在一处记载里出现），可以只写一段，并在文中说明"史料所载仅此"。
  - 段与段之间空一行。不用小标题，不用列表。
  - 人物按时间顺序写：出身 → 主要经历 → 结局。事件写：起因 → 经过 → 结果与影响。
- `sources`：至少一条。优先原始史料（书名 + 篇名），其次是可靠的工具书、学术性百科条目。只列确实用到的。
  - **网络上查到的，写上那一页的完整网址**（具体到篇、卷、条目的那一页，不是网站首页），写在书名或条目名后面，空一格。网站会把它变成可以点的链接。
  - 只有确实查不到网络版本的（如只见于纸本的书），才可以只写书名、篇名、卷章。
  - `sources` 的内容显示在网站上每一条信息的最下面。留空（`[]`）的条目，网站会注明"由 AI 模型 Claude Fable 5.2 凭训练记忆写成，尚未对照史料查证"。所以**没有实际查过的，不要填进 `sources`**。
- `recalled`：可选，列表。凭记忆知道某件事出自哪本书、哪一卷，但没有打开核对过的，写在这里（不带网址）。网站把它单独列出，标明"凭训练记忆标注，尚未核对"。日后查证时，核实一条就把它从 `recalled` 挪到 `sources` 并补上网址。

### 写法

- 平实的陈述句。不用"雄才大略""千古一帝"这类评价词，不用反问和感叹。
- 年份写"公元前 221 年"；正文里第二次出现可简作"前 221 年"。
- **数字**（兵力、伤亡、年龄、里程）必须有出处，并在句中交代是谁说的，例如"据《史记》，秦军被坑杀二十余万"。史料数字本身可疑的，写"史称"。
- **引文**只引确有出处的原话，并注明出自哪里；不确定是否原话的不加引号。
- **成语典故**（破釜沉舟、四面楚歌等）可以提，写明出自哪次事件。
- 外国人名、地名用通行的中文译名；第一次出现时不必附原文。
- 圣经相关条目：年代与事件以圣经及《马加比书》等记载为据，并写明出处；与外部史料有出入的地方如实说明。

## 3. 结构文件：查证年份

逐项核对 `data/` 文件里已有的年份（生卒、在位、事件起止），与可靠来源对照。

- **年份用天文纪年整数**：公元前 n 年写作 `1 - n`。公元前 221 年 = `-220`，公元前 1 年 = `0`，公元 1 年 = `1`。
- 约数加 `circa: true`。
- 史料没有记载生年或卒年的，写 `{ unknown: true, approx: <年份> }`。`approx` 只用来在图上画一段渐隐的条，不会显示成数字；按"活跃期前推约 40–50 年"估一个即可。
- 发现已有年份与可靠来源不符：**直接改正**，并在交回的报告里逐条列出（原值、新值、依据）。
- 来源之间有分歧的：取学界通行说法，加 `circa: true`，并在正文里提一句另一说。
- `wikidata`：到 Wikidata 查到本条目的编号（形如 `Q7192`）后填写；查不到保持 `null`。
- `type`（事件）：从 `battle`（战役）、`war`（战争）、`political`（政变、即位、分封等政治事件）、`founding`（建国、立制）、`uprising`（起义）、`cultural`（学术、文化、宗教）、`diplomatic`（出使、和约）、`migration`（迁徙）、`disaster`（瘟疫、地震、饥荒、水旱等灾害；2026-11-28 增设）里选一个。
- 不要改 `id`、`civ`、`faction`、`importance`、`participants`、`reviewed`。认为这些有问题的，写进报告。

## 4. 结构文件：地点

为日后的地图功能做准备。完整规则见 plan.md 4.3，录入时照下面做。

**人物**

```yaml
birthplace: pei              # 出生地（地点 id）
deathplace: changan          # 去世地
places:                      # 主要活动地：都城、封地、任职地、长期征战地、流亡地。2–5 个为宜
  - { place: hanzhong, start: -205, end: -205 }    # 起止年可省
  - { place: changan }
```

**事件**

```yaml
places: [gaixia]             # 发生地，至少一个；战争可以列主要战场、起止地
```

- **填地点 id，不填文字。**
- **查过了、史料没有记载的，写 `unknown`**（如 `birthplace: unknown`）。`null` 表示还没查，交稿时不应再有 `null`。
- 先看 `data/place/` 里有没有这个地点；有就直接用它的 id，**不要改已有的地点文件**。
- 没有的，新建两个文件：

```yaml
# data/place/<id>.yaml         id 用小写拼音或通行英文名，连字符分隔
id: huaiyin
wikidata: null               # 留空，另有专人统一查
lat: null                    # 留空。不要估坐标
lng: null
precision: city              # site 具体地点（战场、宫殿） / city 城邑 / region 只知大致区域
certainty: disputed          # 只有地望有争议时才写这一行
```

```yaml
# locales/zh-CN/place/<id>.yaml
name: 淮阴                    # 当时的地名
modern: 江苏省淮安市           # 今地，必填，写到县市一级
note: ……                     # 可选：地望的争议、另一说
```

- 同一个地方只建一条。古今同地异名（长安、西安）算同一条；位置确实不同的才另建。

## 5. 关系

`data/relation/<组>.yaml` 是人物之间的关系，`locales/zh-CN/relation/<组>.yaml` 是每条关系的说明文字（键是 `起点|终点`）。

- 核对每条关系是否属实，`year`（这层关系最有代表性的年份，用来在图上定位连线）是否落在双方都在世的年份里。
- 类型只有五种：`kin` 亲属、`lord` 君臣、`mentor` 举荐与师友、`ally` 同盟与同袍、`rival` 敌对。
- 说明文字控制在 8 个字以内。
- 可以补充确有依据的重要关系，补充的要在报告里列出。

## 6. 核对状态

每个结构文件有 `reviewed: false`。**只有人工逐句核对过出处之后才改成 `true`**；AI 查证过的仍然是 `false`，网站上会注明"尚未经人工核对"。
